# Security Policy

This policy covers code and artifacts generated by the `natcap/invest`
repository, including the InVEST models, command-line interface,
workbench, and packaging related to distributing the `natcap.invest`
python package on the Python Package Index.

Issues with related repositories should be reported by opening an issue:

* Vulnerabilities in the conda-forge feedstock not present in this repository
  should be reported to <https://github.com/conda-forge/natcap.invest-feedstock>
* Vulnerabilities in the InVEST User's Guide not present in this repository
  should be reported to <https://github.com/natcap/invest.users-guide>

## Supported Versions

We actively patch security vulnerabilities against the latest tagged release
of InVEST and will publish a new bugfix release containing fixes.

## Reporting a Vulnerability

Please **do not open public GitHub issues** for security vulnerabilities.

To report a vulnerability, please use one of the following private channels
(GitHub Private Vulnerability Reporting preferred):

1. **GitHub Private Vulnerability Reporting**: Navigate to the ["Security and quality" tab](https://github.com/natcap/invest/security) of
   this repository and select "Report a vulnerability".
2. **Email**: Send a detailed report to <natcap-software@lists.stanford.edu>.

Please include the following details in your report:

* A description of the issue and its potential impact.
* Steps to reproduce the bug (including proof-of-concept code if available).
* Any specific configurations or environments required to trigger the issue.
* The InVEST version or versions known to exhibit this issue.

## Our Response Process

* **Acknowledgment**: You will receive an acknowledgment within 72 hours\*.
* **Triage**: Our team will evaluate the report and update you on the status
  within 7 days\*.
* **Fix**: If verified, we will coordinate a patch and appropriate notification
  across relevant channels and coordinate with you if an embargo is necessary.
  Fixed vulnerabilities will be disclosed via a GitHub Security Advisory, with
  credit to the reporter unless anonymity is requested.

\*Please be aware that our software team adheres to the [Stanford University
administrative calendar](https://cardinalatwork.stanford.edu/benefits-rewards/time-leaves/university-holiday-schedule),
which includes occasional holidays and a two-week winter closure. During
University closures, we will do our best to respond as soon as we can,
but cannot guarantee adherence to specific timelines.

## Out of Scope

InVEST is distributed as desktop, CLI, and Python-library software that
users run locally against data they supply themselves. Given this, the
following are considered out of scope:

* Theoretical attacks without a realistic proof of concept.
* Standard automated scanner outputs without actionable validation.
* Issues that assume a level of local access greater than what
  running InVEST itself requires.
* Denial-of-service or resource-exhaustion from a user's own oversized or
  malformed input data on their own local run. (Note: a crafted file
  that causes code execution or data exfiltration when opened by another,
  unsuspecting user, such as a shared malicious raster/vector file,
  is in scope.  Security issues with plugins should be reported via the
  instructions in the Plugin Registry repo:
  <https://github.com/natcap/invest-plugin-registry>)
* Vulnerabilities in third-party dependencies (GDAL, numpy,
  etc.) that are not specific to how InVEST uses them. Please report these
  upstream, and optionally notify us at
  <natcap-software@lists.stanford.edu> so we can track the update.
* Vulnerabilities that only affect unsupported/end-of-life versions of
  InVEST (see Supported Versions above).
